# CraftOS-Tweaked to-do list

Items marked **(you)** need something only the maintainer can do (an account
setting, a secret, a decision, or a tool that is not available in CI). The rest
are code tasks. Search the code for `TODO(slammingprogramming)` to find the
matching spots.

## 1. Do these first (you)

### 1.1 Turn on GitHub Actions
Forks have Actions disabled until you enable them.
1. Open <https://github.com/slammingprogramming/craftos-pc-tweaked/actions>.
2. Click **I understand my workflows, go ahead and enable them**.
3. Check *Settings → Actions → General → Workflow permissions* allows workflows
   to run (the release workflow asks for `contents: write` itself).
4. Push a commit, or use **Actions → CI → Run workflow**, then read any failing
   logs (Windows/vcpkg is the most likely first failure).

### 1.2 Make a release (this fixes the "release trigger" problem)
The release workflow now starts on a **tag push**, not on the "release
published" event. Releases created with the default `GITHUB_TOKEN` never start
other workflows, so listening for them could not work. To release:

```sh
git tag v2.8.4-tweaked.1        # a tag containing "-" is marked as a pre-release
git push origin v2.8.4-tweaked.1
```

The workflow builds everything, creates the GitHub Release if it does not
exist (you can also create it yourself in the web UI first), and uploads the
Windows and Linux packages and `sha256-hashes.txt`. You can re-run it for an
existing tag from the Actions tab (choose the tag as the ref).

*Optional:* if you want other workflows to react to releases, create the
release with a token that is not `GITHUB_TOKEN`: make a fine-grained personal
access token (GitHub → Settings → Developer settings → Personal access tokens →
Fine-grained tokens) for this repository with *Contents: read and write*, save it
as a repository secret (Settings → Secrets and variables → Actions → New secret,
e.g. `RELEASE_TOKEN`), and use it as `GH_TOKEN` in the "Create release if
needed" step.

### 1.3 Decide the version scheme
`CRAFTOSPC_VERSION` in `src/util.hpp` is still upstream's `v2.8.4`, and the
update checker offers an update whenever the latest release tag differs from it.
Pick a scheme (the example above uses `v2.8.4-tweaked.1`), then set
`CRAFTOSPC_VERSION` to match before each release. While `CRAFTOSPC_INDEV` is
`true` the update check is disabled.

## 3. Generated or external files that need you

* **`configure`** is generated from `configure.ac`. The committed copy was
  already out of date (generated by Autoconf 2.69 for "CraftOS-PC 2.6"), so I
  changed the project name and output binary name in it by hand to match
  `configure.ac`. To regenerate it properly on a machine with `autoconf`:
  `autoreconf -fi && git add configure && git commit`.
* **Xcode project (iOS, macOS app)** is not in the repository (`CraftOS-PC.xcodeproj`
  is git-ignored). When you create or update it, use the bundle identifier
  `io.github.slammingprogramming.CraftOS-Tweaked` (and `...-iOS` for iOS; the same
  string is hard-coded in `src/platform/ios_iap.mm`), product name `CraftOS-Tweaked`
  and executable `craftos-tweaked`.
* **iOS** is sideload-only: build an unsigned `.ipa` and publish it (for example
  through an AltStore/SideStore source). CI does not build iOS yet.
* **Android** (F-Droid, Obtainium): the app id is now
  `io.github.slammingprogramming.craftostweaked`. CI does not build Android yet.
  Obtainium installs signed APKs attached to GitHub Releases, so we need an Android
  signing keystore stored as a repository secret and an APK build job. F-Droid builds
  from source from its own metadata repository (<https://gitlab.com/fdroid/fdroiddata>),
  so it needs a metadata file and a build recipe, not a CI job here.
* The IDE metadata in `resources/android-project/.idea/` still uses the old
  `craftos2-android` module names; Android Studio regenerates it.

## 4. Compatibility items to change later

These were left alone on purpose so existing programs, saves and plugins keep working.

* **`_HOST`** (`src/Computer.cpp`) still reports `ComputerCraft x.y (CraftOS-PC ...)`
  because Lua programs detect the emulator by it. Change it to match what the latest
  CC: Tweaked reports (check the current CC: Tweaked `_HOST` format and version).
* **`os.version()`** comes from the ROM's `bios.lua` (the `craftos2-rom` repository),
  not from this code (`resources/CraftOSTest.lua` also checks for `"CraftOS 1.9"`).
  Update both to whatever the latest CC: Tweaked uses.
* **Data and ROM locations**: the data directories (`%appdata%\CraftOS-PC`,
  `~/Library/Application Support/CraftOS-PC`, `$XDG_DATA_HOME/craftos-pc`, `~/.craftos`)
  and the ROM path (`/usr/share/craftos`, `/usr/local/share/craftos`, `/craftos` in the
  WebAssembly build) are unchanged. Change them to match CC: Tweaked **with a migration**
  that moves existing saves, or users lose their computers. CI log paths and
  `README.md` mention them too.
* **Plugin API**: `api/CraftOS-PC.hpp`, the `CRAFTOSPC_*` macros and the
  `craftos_pc_version` field keep their names for plugin compatibility. When
  renaming, add a `CraftOS-Tweaked.hpp` that includes the old header so existing plugins still build.
* **`CraftOS 1.9`**-style compatibility strings and the `ccpcTerm` protocol extension name are unchanged.

## 5. Updater

The in-app update checker now queries this repository's releases
(`CRAFTOSTWEAKED_REPO` in `src/util.hpp`) and shows a notification with a link to
the release page. In-place updating (downloading and running an installer) is disabled
unless `CRAFTOSTWEAKED_AUTOUPDATE` is defined, because releases do not contain
installers. To enable it later: produce `CraftOS-Tweaked-Setup.exe` (optionally
`CraftOS-Tweaked-Setup_Delta-v<version>.exe`) and `CraftOS-Tweaked.dmg`, upload them
with `sha256-hashes.txt` to each release, and build with `-DCRAFTOSTWEAKED_AUTOUPDATE`.
Windows installer and macOS signing/notarization need your own certificates stored as
repository secrets.

## 6. Crash reports

Upstream's crash-log upload (`CRASHREPORT_API_KEY`, `uploadCrashDumps` in
`src/platform/win.cpp`) sends data to an endpoint owned by upstream. CraftOS-Tweaked
builds do not define the key, so it is compiled out. Only enable it with your own
endpoint.

## 7. Packaging not done yet

CI/Release currently produces portable Windows (x64/ARM64) and Linux (x86_64) archives.
Not built: macOS app/dmg, iOS, Android, Windows installers, AppImage, and distro
packages (the upstream PPA, AUR and Homebrew publishing was removed because it
pushed to upstream's accounts). Linux binaries are built on `ubuntu-latest` and use
system libraries.
